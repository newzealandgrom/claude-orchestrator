# Лимиты и контекст

[English version](../en/limits-and-context.md) · [README](../../README.ru.md) · [Руководство по использованию](usage-guide.md)

Как оркестратор решает, сколько работы запускать, на какой модели и когда сохранять своё состояние. Источники:
`skills/team-orchestrator/scripts/limits.py`, `statusline.py`, `checkpoint.py` и
`skills/team-orchestrator/references/limits-and-context.md`.

Всё работает локально и только на чтение. В скриптах нет сетевого кода: они читают счётчики использования, id моделей,
время и тексты сообщений о лимитах из транскриптов Claude Code и пишут небольшие файлы состояния в
`~/.claude/team-orchestrator/`. **Все числа, кроме официальных данных строки состояния, — оценки.**

## Запуск

```bash
python3 skills/team-orchestrator/scripts/limits.py            # для человека
python3 skills/team-orchestrator/scripts/limits.py --json     # для машины
python3 skills/team-orchestrator/scripts/limits.py --config ~/my-limits.json
python3 skills/team-orchestrator/scripts/limits.py --session-file <transcript.jsonl> --context-window 1000000
```

Остальные флаги: `--hook [EVENT]` (режим хука, см. ниже), `--always` и `--cache-sec N` (только в режиме хука),
`--now <ISO-время>` (для тестов). При ручной установке скрипты есть и в `~/.claude/team-orchestrator/`.

Вывод для человека выглядит так (значения для примера):

```
mode: ECONOMY
session 5h: 18400000 / 27000000 units (68%, cap: observed-limit), block 2026-10-13T09:10:00+00:00 -> 2026-10-13T14:10:00+00:00
week 7d:    61000000 / ? units (n/a)
model fable   ok       week 9000000 / ? (n/a)
model opus    ok       week 30000000 / ? (n/a)
context: 410000 / 1000000 tokens (41%) -> ok  [<session>.jsonl]
actions:
  - ECONOMY: max 2 parallel heavy agents; no refute panels; prefer haiku for search/build, sonnet for analysis; reviews only for risky changes.
```

## Источники данных (от лучшего к худшему)

1. **Официальные данные строки состояния.** `statusline.py` сохраняет то, что Claude Code передаёт строке состояния, в
   `~/.claude/team-orchestrator/statusline.json`: `rate_limits.five_hour` / `seven_day` (`used_percentage`,
   `resets_at`) — для подписчиков Pro/Max, и `context_window.used_percentage` — для всех. `limits.py` использует файл,
   только если ему меньше 10 минут. Если данные есть, они заменяют расчётные проценты за 5 часов и 7 дней и время
   конца блока (`cap_source: statusline`).
2. **Локальные транскрипты.** `~/.claude/projects/*/*.jsonl` и `~/.claude/projects/*/*/subagents/*.jsonl`, файлы,
   изменённые за последние 8 дней; сканируются все проекты, так что учёт идёт по всей машине. `usage` и `model`
   каждого ответа ассистента считаются один раз (дедупликация по id сообщения).
3. **Реальные события лимитов в транскриптах.** Ошибки вида
   `You've hit your session limit · resets 3:50am (Europe/Berlin)` или `You've hit your Opus limit · …` и
   предупреждения вида `You've used 85% of your session limit`. По ним калибруются потолки.
4. **Конфиг** `~/.claude/team-orchestrator/limits.json` переопределяет потолки, веса, пороги и окно контекста.

Скрипт не видит: расход с других устройств, чаты claude.ai и другой `CLAUDE_CONFIG_DIR`.

## Единицы расхода

```
units = вес_модели × ( input + 5·output + 0.1·cache_read + 1.25·cache_write_5m + 2·cache_write_1h )
```

Запись в кэш без разбивки на 5m/1h считается как 5m. Веса по умолчанию (`model_weights`, относительная стоимость
семейства): fable 2.0, opus 1.0, sonnet 0.6, haiku 0.2, other 1.0. Семейство определяется по подстроке в id модели
(`fable`, `opus`, `sonnet`, `haiku`).

## Окна и потолки

- **Блоки сессии.** Расход группируется в 5-часовые блоки, начинающиеся с первого запроса после конца предыдущего
  блока. Если в сообщении о лимите указано время сброса, блок привязывается к `[сброс − 5 ч, сброс)`.
- **Неделя.** Скользящие 7 дней.
- **Калибровка потолка сессии.** Для каждого реального события лимита сессии единицы, израсходованные за 5 часов до
  него, — одна оценка потолка. Для каждого предупреждения `used N%` (N больше 20) оценка — `units / N`. Берётся
  наибольшая (`cap_source: observed-limit`).
- **До первого срабатывания.** Потолок — самый большой из завершённых прошлых блоков (`cap_source: history-max`),
  это предположение с низкой достоверностью. Если завершённых блоков нет, нет ни потолка, ни процента.
- **Недельные и модельные потолки** калибруются так же — по событиям и предупреждениям о недельном лимите,
  `Opus limit` и `Fable limit` за предшествующие 7 дней.
- **Конфиг главнее.** `session_cap_units`, `weekly_cap_units` и `model_weekly_cap_units` приоритетнее калибровки
  (`cap_source: config`).
- **Разбор времени сброса** понимает формы вроде `resets 3:50am (Europe/Berlin)`, с днём недели или с месяцем и
  числом; неизвестный часовой пояс трактуется как UTC.

## Уровни

Уровень (`mode`) определяется большим из процентов сессии и недели.

| Уровень | Условие | Поведение оркестратора |
|---|---|---|
| normal | ниже 60 % | до 4 тяжёлых (Opus/Fable) агентов параллельно; полная лестница проверок |
| economy | от 60 % | до 2 тяжёлых агентов; Haiku для поиска и сборок, Sonnet для анализа и документации; ревью только рискованных diff; без панелей опровержения; вопросы агентам пачкой |
| critical | от 80 % | новых тяжёлых агентов нет; завершить начатое; чекпоинт; сообщить, что сделано/осталось и когда сброс; только дешёвые обязательные проверки |
| exhausted | от 95 % или активное событие лимита | ничего не запускать; чекпоинт; после сброса возобновить агентов через `SendMessage` |

Два правила из кода:

- **Активное** событие лимита (сессия, неделя или неизвестный тип; время сброса ещё впереди, а если в тексте его нет —
  5 часов для сессии и 1 час для остальных) всегда даёт `exhausted`.
- Пока потолок только `history-max`, пороги понижаются на одну ступень: от 95 % — `critical` (не `exhausted`),
  от 80 % — `economy`. Диапазон 60–80 % в любом случае `economy`.

## Маршрутизация по моделям

Для каждого семейства (`fable`, `opus` и любого, замеченного за 8 дней) недельный расход сравнивается с его потолком:

| Статус | Условие | Маршрутизация |
|---|---|---|
| `off` | активное событие лимита этой модели; недельная доля не ниже `model_thresholds.off` (0.85); сессия `exhausted` (все семейства); либо только для `fable` — сессия `critical` | см. ниже |
| `economy` | недельная доля не ниже `model_thresholds.economy` (0.60) или сессия `critical` | см. ниже |
| `ok` | иначе | как обычно |

Что делает оркестратор:

| Условие | Действие |
|---|---|
| Fable `off` | все роли Fable/`best` работают на Opus с effort max: `Agent(subagent_type, model: "opus", effort: "max")` или `spawn.sh … --model opus --effort max` |
| Fable `economy` | Fable только как судья критичных и протокольных решений; остальные роли Fable -> Opus max |
| Opus `off` | senior-роли -> Sonnet с effort high (или Fable, если доступен); ревью последовательно |
| Sonnet `off` | анализ и документация -> Haiku high или Opus medium (по справочной политике; `limits.py` пока не печатает для этого случая отдельного указания) |

Fable отключается первым, когда бюджет сессии сжимается, потому что он самый дорогой. Переопределение `effort` в вызове
требует Claude Code 2.1.292 или новее. `model: best` в файлах агентов означает Fable, если он есть у аккаунта, иначе
Opus. Без доступа к Fable строки про Fable на практике не применяются.

## Обработка сбоев (всегда включена)

Если в результате или уведомлении агента встречается `rate_limit`, `429` или `You've hit your … limit`, оркестратор:

1. Классифицирует: привязан к модели (имя модели в тексте) или это лимит сессии/недели.
2. Привязан к модели: переводит это семейство на запасной маршрут (таблица выше) и перезапускает шаг, возобновляя
   упавшего агента через `SendMessage(to: <id>, …)` с переопределением модели/усилия; если возобновить нельзя — новый
   агент с переопределениями.
3. Сессия/неделя: считает это `exhausted` — останавливается, пишет чекпоинт, сообщает вам время сброса. После сброса
   каждого упавшего агента возобновляет фразой «Limit reset — continue from where you stopped and return the result in
   the agreed format.»

В долгих прогонах ворота перезапускаются после завершения каждого агента.

## Контекст оркестратора

Модель не может выполнить `/compact` или `/clear` — только вы. Поэтому оркестратор бережёт контекст (отдаёт всё чтение
агентам, просит отчёты `file:line — факт`, возобновляет агентов вместо повторного брифинга) и реагирует на заполнение:

| Заполнение | Статус | Действие |
|---|---|---|
| ниже 50 % | ok | — |
| от 50 % | `checkpoint` | переписать `## Checkpoint` плана (сделано, id запущенных агентов, следующий шаг, открытые решения, ключевые пути); самому файлы больше не читать |
| от 75 % | `compact` | чекпоинт, затем просьба к вам: `/compact keep: plan <path>, running agent ids, next step` (или начать новую сессию и продолжить по плану) |

Заполнение берётся из снимка строки состояния, если он относится к той же сессии, иначе — из самого свежего
транскрипта проекта текущего каталога (последний ответ ассистента не из sidechain: input + cache read + cache write +
output токены). Окно — `context_window` из конфига, иначе значение от строки состояния, иначе 200k (1M, если когда-либо
наблюдалось больше 200k или в id модели есть `[1m]`).

После `/compact`, `/clear` или resume хук `SessionStart` запускает `checkpoint.py --hook`: он берёт самый свежий
`.claude/plans/*.md` с `Status: in-progress` в шапке и выводит первые 12 строк, раздел `## Checkpoint` (до 80 строк) и
текущую строку о лимитах. Claude Code добавляет этот вывод в новый контекст. Если плана in-progress нет, хук ничего не
печатает.

Необязательная настройка (в Claude Code, не в этом плагине): `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`,
`CLAUDE_CODE_AUTO_COMPACT_WINDOW`.

## Хуки

| Событие | Команда | Эффект |
|---|---|---|
| `SessionStart` (`compact\|resume\|clear`) | `checkpoint.py --hook` | возвращает чекпоинт и строку о лимитах |
| `PostToolUse` (`Agent`) | `limits.py --hook PostToolUse` | указание через `additionalContext`, если состояние ухудшилось или изменилось |
| `UserPromptSubmit` | `limits.py --hook UserPromptSubmit --cache-sec 120` | то же, один раз на запрос |

Как ведёт себя `limits.py --hook`: последнее состояние (режим, статусы моделей, статус контекста) он хранит в
`~/.claude/team-orchestrator/last-state.json` и говорит, только когда оно изменилось. Если всё в порядке, первый
вызов тоже молчит. Отчёты кэшируются в `last-report.json` на `--cache-sec` секунд (по умолчанию 60, для
`UserPromptSubmit` — 120), чтобы не перечитывать транскрипты при каждом вызове. Любое исключение уходит в stderr, а
хук завершается с кодом 0, поэтому сессию он сломать не может. Сообщение выглядит так:
`[team-orchestrator limits] mode=economy session=68% week=n/a context=41% models=fable:ok,opus:ok :: ECONOMY: …`.
`--always` включает вывод даже без изменений.

При установке плагином хуки берутся из `hooks/hooks.json`. При ручной установке добавьте `--hooks` к `install.sh`: он
зарегистрирует те же три хука, указывающие на `~/.claude/team-orchestrator/`.

## Строка состояния

`statusline.py` печатает одну строку и сохраняет описанный выше снимок:

```
Opus 5.5 · ctx 41% · 5h 63% ↻14:50 · 7d 22%
```

Части `5h` и `7d` появляются, только если Claude Code передаёт `rate_limits` (Pro/Max); `ctx` — когда доступен процент
контекста; `↻` — локальное время сброса. Плагин не может поставлять строку состояния, поэтому включите её сами:

```bash
./install.sh --statusline-only        # для пользователей плагина; при ручной установке — флаг --statusline
```

Скрипт копирует файлы в `~/.claude/team-orchestrator/` и прописывает `statusLine` в `~/.claude/settings.json` (сначала
резервная копия). Если у вас уже была строка состояния, её команда сохраняется в `ORCH_STATUSLINE_NEXT`, а её вывод
дописывается после `|` (таймаут 5 секунд). Вручную:

```json
"statusLine": { "type": "command", "command": "python3 /ABS/PATH/statusline.py" }
```

`./uninstall.sh` восстанавливает прежнюю строку состояния.

## Конфигурация

Файл: `~/.claude/team-orchestrator/limits.json`, либо `$ORCH_LIMITS_CONFIG`, либо `--config`. Используется первый
существующий; его ключи накладываются на значения по умолчанию (вложенные объекты сливаются по ключам). Шаблон:
`examples/limits.example.json`.

```json
{
  "session_cap_units": null,
  "weekly_cap_units": null,
  "model_weekly_cap_units": { "fable": null, "opus": null },
  "model_weights": { "fable": 2.0, "opus": 1.0, "sonnet": 0.6, "haiku": 0.2, "other": 1.0 },
  "thresholds": { "economy": 0.60, "critical": 0.80, "exhausted": 0.95 },
  "model_thresholds": { "economy": 0.60, "off": 0.85 },
  "context_window": null,
  "context_thresholds": { "checkpoint": 0.50, "compact": 0.75 }
}
```

Примеры:

```json
{ "session_cap_units": 40000000 }
```
Фиксирует потолок 5 часов. Подходит, когда вы увидели реальное число в выводе `limits.py` после записанного сообщения
о лимите, либо когда оценка постоянно промахивается.

```json
{ "thresholds": { "economy": 0.50, "critical": 0.70, "exhausted": 0.90 } }
```
Более осторожный оркестратор.

```json
{ "context_window": 200000, "context_thresholds": { "checkpoint": 0.40, "compact": 0.65 } }
```
Принудительно окно 200k и более ранние чекпоинты.

```json
{ "model_weekly_cap_units": { "fable": 6000000 } }
```
Задаёт Fable недельный потолок, чтобы его доля могла дойти до `economy`/`off` ещё до реальной ошибки лимита Fable.

## Если что-то не так

**Режим `economy` (или `critical`), а лимит я не выбирал.** До первого записанного события лимита потолок — самый
большой завершённый прошлый блок (`cap_source: history-max`). Если текущий блок больше всех предыдущих, процент
по построению выше 100 %, а при короткой истории потолок занижен. Запустите `limits.py` и посмотрите `cap_source`.
Что делать: задать `session_cap_units`; включить строку состояния (Pro/Max), чтобы использовались официальные
проценты; либо поднять `thresholds`.

**`cap: history-max` и проценты `n/a`.** За последние 8 дней ещё нет завершённого блока, сравнивать не с чем. Режим
остаётся `normal`, пока не накопятся данные (проверки контекста при этом работают).

**Строка состояния пустая.** Проверьте настройки: `statusLine` должна указывать на существующий `statusline.py`
(`python3` должен быть в `PATH`). Claude Code запускает команду строки состояния только после того, как рабочая папка
помечена доверенной, — сначала примите диалог доверия для папки. Выполните
`echo '{}' | python3 ~/.claude/team-orchestrator/statusline.py` — должна напечататься строка. Требование доверия
исходит от Claude Code, а не от этого пакета; подробности — в документации Claude Code.

**В строке состояния нет `5h` / `7d`.** `rate_limits` передаётся только подписчикам Pro/Max. Иначе используются оценки
по транскриптам.

**Контекст показывает `unknown`.** Для текущего каталога не найден транскрипт, а снимок строки состояния старше
10 минут или относится к другой сессии. Включите строку состояния или передайте `--session-file`.

**Проценты расходятся с `/usage`.** Это ожидаемо: оценки учитывают только транскрипты этой машины и фиксированную
структуру цен. Доверяйте официальным числам; если хотите, чтобы оценки были ближе, задайте потолки в конфиге.

**Хук никогда ничего не говорит.** Так задумано: пока всё `normal`/`ok` и ничего не менялось, он молчит. Посмотрите
`~/.claude/team-orchestrator/last-state.json` или запустите `limits.py --hook --always`.

**Хуки срабатывают дважды.** Вы поставили плагин и дополнительно запустили `install.sh --hooks`. Уберите одно из двух
(`./uninstall.sh` удаляет записи ручной установки).

**Версия Python.** Нужен 3.9+ (`zoneinfo`); на более старых версиях часовые пояса в текстах сброса заменяются на UTC.
